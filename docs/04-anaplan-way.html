The Six-Phase FCR Delivery Methodology

FCR delivery follows Anaplan's standard App delivery phases, adapted for the consolidation-specific configuration workflow. Understanding the phases helps you set correct expectations with customers and know which activities belong where.

📚 Reference Document

The Anaplan Way for Applications Methodology — Complete methodology for delivering structured application implementations. Available on Anaplan Seismic for partner access.

1

Pre-Project

The engagement prep phase. Deliverables include:

  • Requirements discovery with the customer — entity hierarchy, chart of accounts, consolidation methods, currencies
  • Requirements workbook completed (entity, account, ownership, integration details)
  • Tenant type decision locked: 10-dim, 11-dim with Group, or 14-dim IFRS accelerator
  • Group dimension decision documented and signed off — irreversible after provisioning
  • Data availability confirmed: which GL systems, which entities, which need account mapping
  • Tenant provisioning request submitted (3–5 day lead time)
2

Configuration

Build the FCR tenant based on confirmed requirements:

  • Import and configure all dimensions: entity hierarchy, account dimension, custom dimensions
  • Configure ownership structure, consolidation methods, and ultimate rate calculator
  • Set up consolidation rules: ARAP elimination, NCI, equity method, intercompany matching
  • Configure currency dimension and assign P_conversion parameters to accounts
  • Enable journals feature flag; configure journal security and definitions
  • Build data integration: staging tables, member mappings, import definitions, clear data settings
3

Data Load & Reconciliation

Load source data and validate the consolidation output:

  • Open required periods; load trial balances from all source GL systems
  • Run currency conversion and consolidation (Run All)
  • Compare consolidated statements to prior system output period-by-period
  • Run validation reports: Validations Open Period and Movement Validations
  • Investigate and resolve differences — document known and accepted variances
4

User Acceptance Testing

Customer-led validation of the configured system:

  • Finance team and controllers run UAT in the configured tenant
  • Test all consolidation methods, journal entry, intercompany matching, period initialization
  • User training: finance team, controllers, system administrators
  • UAT sign-off before cutover
  • Identify and resolve any outstanding gaps
5

Parallel Run

Operate old and new systems simultaneously for at least one close cycle:

  • Strongly recommended — run both systems for at least one month-end period
  • Finance team produces consolidated statements in both systems and compares
  • Identifies any remaining configuration gaps under real operating conditions
  • Builds user confidence before decommissioning the prior system
  • Document final reconciliation sign-off
6

Cutover & Hypercare

Go-live and initial production support:

  • Final data load with production sign-off balances
  • Production security configuration: user roles, data access, folder permissions
  • Handover documentation: configuration guide, admin procedures, period-end checklist
  • Hypercare: Anaplan Professional Services on standby for first 1–2 live close cycles
  • Knowledge transfer to internal super-users / center of excellence
ℹ FCR-Specific Phase Notes

The tenant type decision and group dimension decision in Phase 1 are critical and irreversible. Unlike IFP where Session Zero can be re-run, FCR provisioning decisions cannot be changed after the tenant is created. These must be locked before any provisioning request is submitted. A missed decision here = a full re-provisioning and re-implementation.

Two Customer Types

🌱 Greenfield FCR

  • No existing consolidation tool; first-ever automated group consolidation
  • Chart of accounts may need significant cleanup for FCR requirements
  • Data quality work is often the largest project component
  • Opportunity to build a clean, tag-consistent account structure from the start
  • Risk: Customer may not fully understand what consolidation requires until they see it

🔁 Migration from Legacy System

  • Migrating from HFM, Cognos Controller, OneStream, or similar
  • Historical consolidated data must be loaded or recreated
  • Customer has existing consolidation knowledge — but FCR will feel different
  • Parallel run is essential to validate parity with prior system
  • Risk: Customer expects FCR to work exactly like the old system; manage expectations on approach differences
