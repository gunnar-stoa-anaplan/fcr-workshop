Facilitator Guide

Setup checklist, lab answer keys, known issues, and how to support a self-paced cohort

ReferenceFacilitator Only
🎓 For Workshop Facilitators Only

This page is for whoever administers and supports the self-paced workshop. It covers setup, lab answer keys, known product issues, and resources to share. Keep this link to the support team — do not include it in participant welcome emails.

Pre-Workshop Checklist

Complete these before enrolling participants. Items marked [3–5 days] need a longer lead time.

Pacing & Effort Guidance

The workshop is self-paced — there is no fixed schedule. Use the estimates below to help participants plan their time and to spot when someone is stuck. Most participants spend an hour or two a day and finish over a couple of weeks. Effort includes reading, watching the walkthroughs, and completing the labs.

Table 30: Pacing & Effort Guidance
Module Pages Estimated Effort Notes
Getting Started 01–04 ~1–2 hours Mostly reading. Make sure tenant access is confirmed before participants reach the first lab.
Data Model & Configuration 05–10 ~5–6 hours Labs A–C. The heaviest module. Clear Data Settings (Lab C) is the most critical concept — flag it in your support channel.
Consolidation Engine 11–14 ~5 hours Lab D spans most of this. Covers currency conversion, journals, consolidation rules, and intercompany elimination.
Period Management 15–17 ~2–3 hours Lab E. The FX Rate Override security gotcha and the Mac/Excel add-in limitation come up here.
Advanced Topics 18–19 ~1–1.5 hours Security is conceptual; Narrative Reporting is a short walkthrough on a separate tenant.
Reference 20–21 ~45 min Q&A, best practices, roadmap, and partner collaboration. Worth revisiting during a first live implementation.

Lab Answer Keys

Use these expected outcomes to verify participant progress during and after each lab. These are the observable results a participant should be able to confirm before moving on.

Lab A — Data Model Setup

  • ✅ Two custom dimensions created: Cost Center (Type: Other) and Product (Type: Other)
  • ✅ Both dimensions added to the Consolidation Model (Models → Model → plus sign)
  • ✅ Default Reporting Member and Default Input Member set on both custom dimensions
  • ✅ Entity hierarchy imported; Company/Intercompany/Group dimensions auto-populated after Save → Process
  • ✅ Currencies configured: USD, EUR, GBP (min. 3)
  • ✅ Account dimension imported with correct attributes (Name, Caption, Tags, Classification, Operator, P_conversion)
  • ✅ No errors when running a default report
  • ✅ Save → Process completed after every metadata change — participant can demonstrate this habit

Lab B — Ownership Setup

  • ✅ Consolidation Methods configured: Global (>50% to ≤100%), Proportional (=50%), Equity (20–50%)
  • ✅ All entities have ownership percentages entered in the Direct Ownership table
  • ✅ Ultimate Rate Calculator run — Managed Ownership table populated
  • ✅ Each entity's consolidation method automatically assigned based on ownership %
  • ✅ Entity dimension has Holding Company flag set for appropriate entities in each subgroup
  • ✅ Total Group tag present in Entity, Company, AND Group dimensions (verify by checking Direct Ownership table — all three left-hand dimensions visible)

Lab C — Load Trial Balance

  • ✅ Two staging tables created (one for each GL source file)
  • ✅ Mapping table created for CAM (Central American) entities — different chart of accounts
  • ✅ Two import definitions created with correct field mappings: Scenario = Fixed → Actuals; DataView = Fixed → Value; Entity = Match Name; Period = Match Name; Account = Map
  • ✅ Clear Data Settings configured on each import definition (not left at default additive)
  • ✅ Required periods opened in Configure Open Periods table before data load
  • ✅ Workflow created and run to execute both imports
  • ✅ Trial balance visible in a default report — entity data loads cleanly, no doubled amounts

Lab D — Consolidation Engine

  • ✅ GBP set as additional reporting currency (reporting = true, triangulate = true, rate operator = divide)
  • ✅ FX rates entered for 2024 P12 (EUR and GBP; USD = 1 as base)
  • ✅ Run All executed for 2024 P12
  • ✅ E13 Berlin shows EUR ~190 and USD ~224 for the cash line in Consolidated Financials by Entity
  • ✅ Journal entry posted: Debit Cost of Sales (IC=3RD, Movement=Closing), Credit Accounts Payable (IC=3RD, Movement=Increase)
  • ✅ Journal visible in Consolidated Financials by Audit → Contribution → Reclass column
  • ✅ ARAP intercompany elimination rule configured, Active = true
  • ✅ IC balances eliminated — visible in Consolidated Financials by Audit report under IC Elimination audit column

Lab E — New Period + Cash Flow

  • ✅ Global Variables updated: Current Year = 2025, Current Period = P1
  • ✅ 2025 P1 (and optionally P2) added to Configure Open Periods
  • ✅ Exchange rates entered for new periods
  • ✅ FX Rate Overrides entered for London accounts (Security → Consolidation = All required first)
  • ✅ Copy Opening run — prior period closing balances carried forward as opening balances
  • ✅ Trial balance loaded for 2025 P1 (London and Paris entities)
  • ✅ Consolidation run; Validations Open Period report shows green checkmarks
  • ✅ Movement Classifications created (Current BS, GPE/depreciation minimum) and assigned to balance sheet accounts
  • ✅ Cash flow calculation rules configured (header + detail rows) for key cash flow lines
  • ✅ Cash flow statement visible in reporting with populated values after running the calculation

Known Product Issues & Workarounds

Issues documented from the April 2026 London workshop and prior deliveries. Check Anipedia release notes before each workshop to see if any of these are resolved in the current version.

Table 31: Known Product Issues & Workarounds
Issue Symptom Workaround
Journals feature flag not self-service Journals module does not appear after enabling journal permissions in Security Feature flag must be enabled in the Excel settings file. For brand-new tenants, may require a support ticket to Anaplan. Pre-enable on all participant tenants before participants start.
FX Rate Override + button missing The + (add) button does not appear in the FX Rate Override web form Security → Role Authorizations → Consolidation → set to "All" → Save. Button appears immediately after save.
Total Group tag missing Entity, Scenario, and Intercompany dimensions not visible in Direct Ownership table left panel; reports fail Verify Total Group tag exists in all three of: Entity dimension, Company dimension, AND Group dimension. Run Save → Process after adding missing tag.
Clear Data Settings left at default Data doubles or triples after multiple trial balance imports Always configure Clear Data Settings on every import definition before the first load. "Staging Unique Values" scoped to the period dimension is the standard setting for trial balance imports.
IC Matching report bug (April 2026 version) Intercompany Matching report shows unexpected or incorrect results after running matching Treat completing the matching configuration as the exercise goal. Facilitator should demo the expected correct report output from a pre-configured tenant. Expected to be fixed in a future release — check current release notes.
Conversion troubleshooting — 7 common causes Currency conversion results not appearing or incorrect after Run All Walk through the 7-step checklist: (1) rates entered, (2) reporting currency flag set, (3) P_conversion attribute on accounts, (4) conversion rules active, (5) new movement added to conversion rule, (6) historical conversion type, (7) YTD balances. This checklist covers ~90% of conversion issues.
Period must be opened before data load Data load fails silently or returns error; data not appearing in reports after import Add the period to Configure Open Periods table before running any data import. This is opposite to most consolidation systems — warn participants explicitly at the start of the Data Integration module.
Save → Process not run after metadata changes Changes to dimensions or model settings appear not to take effect; auto-generated dimensions (Intercompany, Group) not updated Run Save → Process after every metadata change. Build this as a habit from Lab A onward. If participants see unexpected behavior, the first troubleshooting step is always: "Did you Save → Process?"
Mac users cannot use Excel add-in Balance sheet continuity schedule, cash flow adjustment forms, and FX Rate Override (older versions) not accessible Mac users must use a Windows VM. Identify Mac users during enrollment and set expectations. The 5-week post-workshop tenant access allows PC-based completion of deferred exercises.
Month-end rollover wipes movement data Balance sheet continuity movements from current period disappear after running rollover Rollover must only be run at the very start of the cash flow process — never mid-process. Emphasize this during the Balance Sheet & Cash Flow module before participants run any rollover steps.

Common Participant Questions

These come up at virtually every delivery. Have crisp, confident answers ready.

Q: "Is the tenant type really irreversible? Can't we just add the Group dimension later?"
Yes, it is completely irreversible. The Group dimension is not an add-on — it changes the fundamental architecture of how intercompany eliminations are structured. You cannot add it to an existing 10-dimension tenant. Emphasize this strongly, especially for participants who are about to start their first FCR project. Get client sign-off on the decision before provisioning.
Q: "Can I add a new dimension after go-live?"
Technically yes, but it is significant work. Every existing report, input form, consolidation rule, and import definition that touches the model will need to be reviewed and potentially updated. The new dimension also needs default members set, data loaded, and all historical data may need to be re-processed. Best practice: get the dimension design right before any data is loaded. If a client asks late in the project, push back hard on scope.
Q: "Should I work with Anaplan Professional Services on my first FCR engagement?"
Strongly recommended. FCR has many subtle configuration dependencies — tags, consolidation rules, account dimension setup — that are easy to get wrong without experience. Anaplan Professional Services support during the sales cycle and early delivery is free of charge. The goal is not permanent Professional Services involvement; it is to accelerate the partner's path to self-sufficiency. Weekly stand-ups during the project are the most effective model. Call Alliances (Mauro's team) to connect.
Q: "We have a typo in a tag in a live system — how do we find all affected rules?"
Export the full chart of accounts with all tags to Excel (from the Accounts dimension). Then export all consolidation rules. Cross-reference the two exports to find any rules that reference tags not present in the chart of accounts. This is the manual process — there is no built-in tag validation in the current version. A tag manager feature is on Anaplan's foreseen roadmap.
Q: "How do we handle matrix consolidation (cross-ownership structures)?"
Matrix consolidation (where Entity A owns a percentage of Entity B which also owns a percentage back, or multi-tier cross-holdings) is not yet available as a built-in feature. It is on the roadmap — expected to be in customers' hands by end of 2026, likely via two "Other" type dimensions with mirroring behavior. For current projects, complex ownership structures need to be discussed with Anaplan Professional Services to find the appropriate approach within existing functionality.

Post-Workshop Resources

📚 Resources to Share with Participants
  • Tenant access: Training tenants remain accessible for approximately 5 weeks after a participant starts. Encourage participants to complete deferred exercises (security configuration, Excel add-in activities for PC users) during this window.
  • Anipedia: Anaplan's official FCR documentation platform (migrated from Zendesk). Technical documentation for all FCR modules, configuration options, and release notes. Point participants here first for reference questions.
  • Anaplan Community (NLP Community): Blog posts and community content. The post by Gregory ("Mr. Documentation") on the run-all process architecture is specifically recommended for understanding decoupled process behavior.
  • Seismic: Partner-facing materials, competitive intelligence, and sales assets. Access via your partner portal.
  • Professional Services on first engagement: Encourage participants to connect with Anaplan Professional Services (Matteo's team) before starting their first FCR customer project. Weekly stand-ups during delivery are the recommended engagement model.
  • Knowledge check (certification quiz): Distributed via Anaplan Academy. Confirm with your Alliances contact (Mauro) that the quiz form is set up.
  • Workshop evaluation form: A separate feedback form should be sent to participants when they complete the workshop. Results feed into workshop improvement cycles.
