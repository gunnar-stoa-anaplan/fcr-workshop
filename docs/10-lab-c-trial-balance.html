Lab C: Load Trial Balance Data

Create staging tables, configure mappings and import definitions, open periods, and validate

Data Model & Configuration45 min
🎯 Lab Objective

By the end of this lab, trial balance data from two source GL systems will be loaded into FCR and visible in the Consolidated Financials report. You will have built the complete integration pipeline: open period → staging tables → member mappings → import definitions → workflow → data load.

📁 Lab Files

This lab uses two trial balance source files from the Files to Share → Data Integration folder:

  • Source 1 — Rest-of-world entities (standard chart of accounts, direct name matching)
  • Source 2 — CAM entities (Central American entities with a different chart of accounts — requires account mapping)

1
Open Periods
5 min
Objective Open the target period so data can be loaded to it. FCR periods are closed by default — you must explicitly open each period before any data load.
  1. 1 Navigate to Maintain → General Configuration → Open Periods
  2. 2 Click the + button to add a new row
  3. 3 Add period 2024 P12
  4. 4 If your workshop requires additional historical periods, add them now as well
  5. 5 Click Save
✅ You're done when...
2024 P12 is visible in the Open Periods table and the page saves without errors.
2
Create Staging Tables
10 min
Objective Create two staging tables — one for each GL source — with columns that exactly match the trial balance file structures.
  1. 1 Navigate to the Integration module
  2. 2 Create the first staging table (Source 1 — rest-of-world):
    • Click New → enter a descriptive name (e.g., TB_Source1)
    • Add column: Entity → type: VARCHAR
    • Add column: Account → type: VARCHAR
    • Add column: Period → type: VARCHAR (format: YYYY PNN, e.g., 2024 P12)
    • Add column: Amount → type: FLOAT
    • Add column: Intercompany → type: VARCHAR
  3. 3 Save the staging table
  4. 4 Create a second staging table (Source 2 — CAM entities):
    • Use the same structure as Source 1 (same column names and types)
    • Name it clearly (e.g., TB_Source2_CAM)
  5. 5 Save
✅ You're done when...
Two staging tables exist in the Integration module — one for Source 1 and one for Source 2. Each has 5 columns with the correct VARCHAR/FLOAT types.
3
Create Member Mappings
10 min
Objective Import the account mapping for CAM entities — they use a different chart of accounts than the FCR model. Source 1 entities use direct name matching and don't require a mapping table.
  1. 1 In the Integration module, navigate to the Mappings section
  2. 2 Click New → create a new mapping table named (e.g., CAM_Account_Map)
  3. 3 Click the import icon → upload the provided CAM account mapping file
  4. 4 After import, review the mapping table and locate:
    • An example of a Range mapping (e.g., source accounts 1000–1099 → Account X)
    • An example of a Wildcard mapping (e.g., source pattern 4* → Revenue account)
  5. 5 Save
✅ You're done when...
The CAM account mapping table is loaded and you can identify at least one Range mapping and one Wildcard mapping in the table.
4
Configure Import Definitions
15 min
Objective Create import definitions for both GL sources, specifying how each column maps to FCR dimensions and configuring Clear Data Settings to prevent data accumulation on re-runs.
  1. 1 In the Integration module, click New Import Definition → name it Import_Source1
  2. 2 Select staging table: TB_Source1
  3. 3 Configure field mappings:
    • Scenario: Fixed → Actuals
    • DataView: Fixed → Value
    • Audit: Fixed → Source GL
    • Entity: Match Name
    • Period: Match Name
    • Account: Match Name
    • Intercompany: Match Name
  4. 4 Configure Clear Data Settings:
    • Select: Staging Unique Values
    • Dimensions to key on: Audit + Period
  5. 5 Save the import definition
  6. 6 Create a second import definition: Import_Source2_CAM
  7. 7 Select staging table: TB_Source2_CAM
  8. 8 Configure field mappings — same as Source 1 except:
    • Account: Map → select CAM_Account_Map
    • Amount: Enable flip credit sign (sign reversal for credit accounts on inbound load)
  9. 9 Set the same Clear Data Settings (Staging Unique Values, Audit + Period)
  10. 10 Save both import definitions
✅ You're done when...
Both import definitions are saved. Source 1 uses Match Name for Account; Source 2 uses the CAM mapping table with sign flip. Both have Clear Data Settings configured.
5
Create Workflow and Load Data
10 min
Objective Build a reusable workflow that runs both import definitions in parallel, then run it and validate data in the Consolidated Financials report.
  1. 1 Navigate to Explorer → find or create a Workshop folder → right-click → New Folder → name it Processes
  2. 2 Right-click the Processes folder → click New Process (note: NOT from the Workflow menu) → name it Load Trial Balance
  3. 3 In the workflow canvas, drag a Data Input task onto the canvas → connect it from the Start button → configure it to run Import_Source1
  4. 4 Drag a second Data Input task → connect it from the Start button (parallel to the first) → configure it to run Import_Source2_CAM
  5. 5 Save the workflow
  6. 6 Click Run to execute the workflow
  7. 7 Monitor the task progress in the Workflow module — both Data Input tasks should complete successfully
  8. 8 Navigate to the Consolidated Financials report (or any default report) → verify data appears for both source systems
✅ You're done when...
Both Data Input tasks complete without errors and data is visible in the Consolidated Financials report for period 2024 P12. You should see figures from both Source 1 (rest-of-world) and Source 2 (CAM) entities.

Lab C Completion Checklist

  • Period 2024 P12 added to Open Periods table
  • Staging table TB_Source1 created with correct VARCHAR/FLOAT columns
  • Staging table TB_Source2_CAM created with same structure
  • CAM account mapping table imported (with Range and Wildcard examples visible)
  • Import definition Import_Source1 configured (Match Name for Account)
  • Import definition Import_Source2_CAM configured (Map for Account + sign flip)
  • Clear Data Settings configured on both definitions (Staging Unique Values)
  • Workflow Load Trial Balance created with two parallel Data Input tasks
  • Workflow run successfully — no errors
  • Data visible in Consolidated Financials report for 2024 P12
🔧 Common Issues & Fixes
Data doubles on re-run
Clear Data Settings was not configured on the import definition. Edit the import definition, set Clear Data Settings to Staging Unique Values (Audit + Period), save, and re-run. The old doubled data may need to be cleared manually first.
Import fails with "column not found" error
The column names in your source file don't exactly match the staging table column names — this comparison is case-sensitive. Open both the source file and the staging table definition and verify each column name character by character.
Consolidated Financials shows no data after the workflow ran successfully
The period is likely not open. Go to Maintain → General Configuration → Open Periods and verify 2024 P12 is in the table. Then re-run the workflow.
CAM entity amounts look wrong (too high, wrong sign)
Check the sign flip setting on the Source 2 import definition. CAM credit accounts need sign reversal on inbound load. If the sign flip is missing or applied incorrectly, P&L and balance sheet figures will be inverted.
Workflow created from Workflow menu instead of Explorer
Workflows (Processes) must be created from the Explorer folder structure — right-click on the Processes folder → New Process. Creating from the Workflow menu does not work the same way and is a common confusion point.
